# Day 6 — 8 November 2026

## Increment 0: requirements, source audit and architecture

### Objective

Define a practical local-first mushroom growth-monitoring system for fixed horizontal camera views of clusters growing from columns, bags, racks or trays. The application should recognize mushrooms generally, track visible clusters across repeated daily captures, measure changes in size/count/development, group results by cultivation unit and batch, and use site-provided environmental records where available.

### Work completed

1. Reviewed the project brief and documented the operating scene, daily image workflow, cultivation-unit hierarchy, image metadata, measurements and model-update requirements.
2. Defined the training/inference split: model training and validation in Google Colab; deployed inference, tracking, analytics, storage and dashboard run locally.
3. Set AMD acceleration as the first local GPU target, with CPU inference required and NVIDIA support optional future work. AMD execution remains unverified until tested on the actual RX 5500 XT and driver stack.
4. Audited the public sources and recorded their roles:
   - Charisis et al. (2025) / Zenodo 15041243 for temporal cluster tracking and growth measurement;
   - MushR (2023) for an original Mask R-CNN implementation, annotations, maturity labels and capture workflow;
   - M18K for reusable dataset/software patterns and the existing Day 1–5 evidence;
   - Wang et al. (2025) for seven-stage developmental concepts;
   - MushroomSegDepth (2026) as an optional depth extension;
   - a six-species image collection as an optional image-classification supplement.
5. Added source/dataset registries, role-specific candidate notes and an explicit exclusion control. Source-specific taxonomies and annotation semantics remain separate.
6. Defined a modular system architecture covering ingestion, model adapters, tracking, growth analytics, environment records, persistence, review queue and model promotion.
7. Kept model choice provisional until dataset annotation schemas and local runtime compatibility are tested.

### Findings that govern the implementation

- No single public source supplies multi-species whole-scene masks, daily grow-unit identity, time-series tracking, maturity taxonomy and target-site environmental data together.
- Charisis is the strongest available temporal cluster-tracking foundation; its actual archive schema and the availability of persistent annotation IDs must be inspected before relying on them.
- MushR provides valuable source code and maturity-labelled COCO annotations, but its oyster-specific maturity classes must remain source-specific.
- M18K is useful for the existing training/evaluation workflow and optional RGB-D investigation. Its current WB-only checkpoint is not the general production model.
- Wang's seven stages inform optional maturity logic; exact training-data reproduction is not a dependency.
- Measurements remain in image-space units until calibration/reference evidence is available.
- Model-generated labels require human review; candidate model releases must pass a fixed regression set before promotion.
